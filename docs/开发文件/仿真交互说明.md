# 仿真交互说明

## 1. 概述

本项目通过后端与ROS2通信，完成与Unity仿真之间的双向交互。后端主要负责发布取药、过期清理、小车归队等任务；仿真通过ROS2话题返回任务状态、车辆状态、药柜状态，后端再进行存储和业务处理。

## 2. 交互架构

核心路径：

- 后端 API 或业务逻辑触发任务
- 通过 `publish_task()` 等接口向ROS2话题发布消息
- Unity仿真订阅这些话题并执行任务
- Unity仿真将状态发布到状态话题
- 后端订阅这些状态话题，更新内部状态存储，并触发回调

## 3. 后端发布任务到仿真

### 3.1 入口文件

- `agent_with_backend/ros_integration/bridge.py`
  - 提供 `init_ros2()`、`publish_task()`、`publish_expiry_removal()`、`publish_return_to_queue()`、`check_ros2_status()` 等方法
  - 做为兼容层，保持旧接口不变

- `agent_with_backend/ros_integration/task_publisher.py`
  - 负责实际创建ROS2发布器并发布任务
  - 通过 `Config().INTEGRATION_MODE` 选择发布模式

### 3.2 任务来源

- `agent_with_backend/backend/controllers/approval_controller.py` 中 `approve_approval()` 会在审批通过后调用 `publish_task(task_id, drug, quantity)`
- 这里的 `publish_task()` 最终会调用 `ros_integration.bridge.publish_task()`

### 3.3 发布话题

- 新格式话题：`/task_topic`
- 旧格式话题：`/task_request`

### 3.4 支持的发布模式

通过环境变量 `ROS_INTEGRATION_MODE` 控制：

- `new`：仅发布新话题 `/task_topic`
- `legacy`：仅发布旧话题 `/task_request`
- `parallel`：同时发布两个话题

### 3.5 消息格式转换

关键适配器：`agent_with_backend/ros_integration/message_adapter.py`

#### backend -> Unity

- `task_id`：任务ID，转为字符串
- `type`：`"0"` 表示取药任务
- `cabinet_id`：来源于 `drug["shelve_id"]`
- `medicine.column`：来源于 `drug["shelf_x"]`
- `medicine.row`：来源于 `drug["shelf_y"]`
- `medicine.count`：取药数量

#### 重要映射

- `shelf_x` → `column`
- `shelf_y` → `row`
- `shelve_id` → `cabinet_id`

#### 过期清理任务

`expiry_to_unity()` 将过期药品数据转换为 `Task` 消息，类型为 `expiry_removal`。

## 4. 仿真状态订阅到后端

### 4.1 入口文件

- `agent_with_backend/ros_integration/state_subscriber.py`
  - 订阅 Unity 仿真返回的状态话题
  - 将消息写入 `RosStateStore`
  - 触发后端回调

### 4.2 订阅话题

- `/TaskState_U`
- `/CarState_U`
- `/CabinetState_U`

### 4.3 状态处理

`StateSubscriber` 会将接收的消息转换为后端格式，并维护以下信息：

- 任务状态
- 小车位置与运行状态
- 药柜库存状态

如果设置了回调（`set_task_state_callback` / `set_car_state_callback` / `set_cabinet_state_callback`），会继续通知业务层处理。

### 4.4 前端展示与状态同步

- `agent_with_backend/api/ros_state_controller.py` 提供 REST 接口：
  - `GET /api/ros/task-states`：获取所有任务状态
  - `GET /api/ros/task-states/<task_id>`：获取指定任务的当前状态
  - `GET /api/ros/car-states`：获取小车当前状态
  - `GET /api/ros/status`：获取 ROS2 连接与统计概览

- 患者界面 `agent_with_backend/web/patient.html`：
  - 审批通过后，会读取 `approval.task_id` 并开始轮询 `ApiClient.getTaskState(taskId)`
  - 用 `task_state` 映射为前端阶段：
    - `0`：任务已创建 / 等待执行
    - `1`：执行中 / 小车取药中
    - `2`：已送达 / 可取药
    - `3`：任务失败
  - 该页面还显示 `pickupReady`、任务进度时间线和“确认取药”按钮。

- 管理员界面：
  - `agent_with_backend/web/ros_monitor.html` 直接展示 ROS2 监控数据（`/api/ros/status`、`/api/ros/task-states`、`/api/ros/car-states`、`/api/ros/cabinet-states`）
  - `agent_with_backend/web/admin_orders.html` 展示数据库 `order_log` 中的订单状态（`pending` / `completed` / `failed`），该状态由后台 `POST /api/orders/<task_id>/complete` 在患者确认后更新。

### 4.5 任务状态同步结论

- 如果 Unity 仿真正确发布 `/TaskState_U` 和 `/CarState_U`，后端 `StateSubscriber` 会更新 `RosStateStore`，前端可通过 API 实时读取。
- 患者页面可正确反映仿真任务“开始”与“完成”状态，因为它直接轮询 `GET /api/ros/task-states/<task_id>`。
- 管理员 ROS2 监控页面可正确反映小车信息和任务状态，因为它从同一 `RosStateStore` 获取最新数据。
- 但管理员订单页的 `order_log` 状态并不直接由 ROS2 任务状态驱动；该页依赖于患者确认取药后由后台接口 `POST /api/orders/<task_id>/complete` 更新。

### 4.6 交互流程图

```
[Unity 仿真]                         [后端 ROS2 集成]                   [前端]
    |                                       |                             |
    |-- /TaskState_U --> StateSubscriber -->|                             |
    |                                       |-- /api/ros/task-states/{id} --> [患者页面轮询]
    |                                       |                             |
    |-- /CarState_U --> StateSubscriber -->|                             |
    |                                       |-- /api/ros/car-states --------> [管理员 ROS2 监控]
    |                                       |                             |
    |-- /CabinetState_U --> StateSubscriber ->|                            |
    |                                                                       |
    |<-- /task_topic or /task_request --- publish_task() <--- [后端业务]  |
    |                                                                       |
                                   [管理员订单页] <-- /api/orders -------- |
                                   [患者确认取药] --> /api/orders/{id}/complete
```

说明：
- Unity 向后端发送状态消息，后端存入 `RosStateStore`。
- 患者界面基于任务ID轮询 ROS2 任务状态；管理员 ROS2 监控页面显示小车和任务状态。
- 订单记录页面展示的是数据库订单状态，与 ROS2 任务实时状态是两个不同的数据源。

## 5. ROS2 节点与执行器管理

核心文件：

- `agent_with_backend/ros_integration/node_manager.py`
  - 初始化 ROS2 节点
  - 创建 `MultiThreadedExecutor`
  - 启动后台线程处理 ROS2 执行器
  - 优雅关闭 ROS2 资源

## 6. 环境与配置

### 6.1 关键环境变量

- `ROS_INTEGRATION_MODE`：`new` / `legacy` / `parallel`
- `ROS_DOMAIN_ID`：ROS2 DOMAIN ID
- `ROS_TCP_ENABLED`：是否启用TCP服务器（`True`/`False`）
- `ROS_IP`：TCP服务器监听地址
- `ROS_TCP_PORT`：TCP服务器端口

### 6.2 启动脚本

- `agent_with_backend/scripts/setup/cli-patient-start.sh`
  - 加载 `.env` 文件
  - 设置 `PYTHONPATH` 包含项目根目录
  - 将 `ros-todo/ros_workspace/install/task_msgs/lib/python3.12/site-packages` 加入 `PYTHONPATH`
  - 尝试 source `ros_workspace/install/setup.sh`

### 6.3 `task_msgs` 依赖

后端发布新话题时依赖 `task_msgs.msg.Task`、`CabinetOrder`、`MedicineData` 等类型。

如果 `task_msgs` 或 `rclpy` 不可用，系统会降级到后备模式并打印警告，但ROS2功能会受限。

## 7. 常用调试命令

```bash
# 查看仿真相关话题
ros2 topic list

# 查看新任务话题消息
ros2 topic echo /task_topic

# 查看旧任务话题消息
ros2 topic echo /task_request

# 查看任务状态与小车状态
ros2 topic echo /TaskState_U
ros2 topic echo /CarState_U
ros2 topic echo /CabinetState_U
```
