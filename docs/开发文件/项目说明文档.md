# 基于 ROS2 的智能药品管理系统 — 项目说明文档

## 1. 系统概述

本项目是一个基于 ROS2 的智能药品管理与自动拣选系统，融合 **AI 医疗咨询助手**与**自动化药房后端**，实现从患者症状描述、AI 用药建议、医生审批到机器人自动取药的完整端到端工作流。

系统支持多角色（患者、医生、管理员）协同操作，提供 Web 管理界面与命令行界面，并通过 ROS2 与 Unity 3D 仿真环境联动，模拟真实药房场景中的机器人取药任务。

---

## 2. 系统主要功能

### 2.1 AI 医疗咨询（核心功能）
- **症状采集表单**：通过引导式问答（Round 1 基础信息 → Round 2+ 症状详情）逐步收集患者信息
- **危险信号检测**：自动识别呼吸困难、高热、胸痛等急重症表征，建议立即就医
- **药品查询**：三层匹配策略（直接匹配 → 同义词扩展 → LLM 生成同义词重试）
- **AI 用药建议**：LLM 驱动，支持过敏检查、剂量计算、多药联用分析
- **审批提交流程**：自动生成用药建议并提交医生审批

### 2.2 药品库存管理
- 药品 CRUD（含软删除、批量导入、CSV 导出）
- 库存操作记录（inventory_transactions 流水账）
- 库存预警（低库存、临期、过期自动清理）
- 药品适应症管理及症状同义词映射

### 2.3 审批工作流
- 审批单创建、查询、待审批列表
- 医生批准/拒绝审批
- 审批通过后自动扣减库存、创建取药订单、向 ROS2 发布取药任务
- 患者端确认取药完成

### 2.4 ROS2 机器人集成
- 发布取药任务到 ROS2 话题（支持新旧话题并行兼容）
- 订阅任务状态、车辆状态、药柜状态
- 过期药品自动清理任务发布
- 小车归队指令
- 支持降级模式和错误重试

### 2.5 智能药品筛选（组件 3）
- 基于症状的药品匹配与评分排序
- 多维筛选（价格、分类、药效）
- 患者适配性过滤（年龄限制、过敏排除）
- 批量筛选与历史记录

### 2.6 用户认证与权限管理
- JWT 双令牌机制（access + refresh token）
- 基于 RBAC 的权限控制（患者/医生/管理员）
- 注册、登录、登出、令牌刷新
- 审计日志记录

### 2.7 Web 管理界面
- **管理仪表盘**：系统状态监控、药品库存概览、用户管理
- **医生界面**：待审批列表、审批操作
- **患者界面**：AI 医疗咨询、审批状态查询
- **药品管理界面**：药品列表、库存调整
- **订单管理界面**：订单查询与追踪
- **ROS 监控界面**：小车状态、任务状态实时监控

## 5. 各组件功能详解

### 5.1 组件 1：药品数据库 & API（drug_controller / database）

| 模块 | 功能 |
|------|------|
| `drug_controller.py` | 药品 CRUD、库存调整、批量导入、CSV 导出、低库存/临期预警、分类搜索 |
| `database/scripts/init_db.py` | 数据库表结构初始化（含 inventory、drug_indications、symptom_synonyms 等表）|
| `database/scripts/seed_drugs.py` | 116 种药品种子数据，599 条适应症记录，30 条同义词映射 |
| `database/approval_manager.py` | 审批表管理（创建、批准、拒绝、完成）|

**API 端点**：
- `GET /api/drugs` — 药品列表（支持 symptom/name/category 过滤、排序、分页）
- `GET /api/drugs/<id>` — 药品详情
- `POST /api/drugs` — 创建药品
- `PUT /api/drugs/<id>` — 更新药品
- `DELETE /api/drugs/<id>` — 软删除药品
- `POST /api/drugs/<id>/adjust` — 库存调整（含流水记录）
- `GET /api/drugs/stats` — 库存统计（总量、过期、低库存、临期）
- `GET /api/drugs/low-stock` — 低库存药品列表
- `GET /api/drugs/expiring-soon` — 临期药品列表
- `POST /api/drugs/batch-import` — 批量导入
- `GET /api/drugs/export` — CSV 导出
- `GET /api/inventory` — 拣货视图（简化字段 + 补货/过期标记）

### 5.2 组件 2：订单 & 审批工作流（approval_controller / order_controller）

| 模块 | 功能 |
|------|------|
| `approval_controller.py` | 审批单创建、查询、批准/拒绝、AI 咨询、表单提交 |
| `order_controller.py` | 取药订单管理 |

**核心流程**：
患者 AI 咨询 → 生成用药建议 → 提交审批 → 医生审批 → 扣库存 → 创建订单 → 发布 ROS2 任务 → 机器人取药

**API 端点**：
- `POST /api/approvals` — 创建审批单
- `GET /api/approvals/<id>` — 查询审批
- `GET /api/approvals/pending` — 待审批列表（医生）
- `POST /api/approvals/<id>/approve` — 批准（自动扣库存+发ROS2任务）
- `POST /api/approvals/<id>/reject` — 拒绝
- `POST /api/approvals/<id>/complete` — 患者确认取药完成
- `POST /api/consultation` — AI 医疗咨询（多轮对话）
- `POST /api/form/submit_basics` — 提交基础信息

### 5.3 组件 3：智能筛选系统（screening/）

| 模块 | 功能 |
|------|------|
| `screening_routes.py` | 筛选 REST API 路由 |
| `screening_service.py` | 药品筛选主服务（症状匹配、过滤、排序）|
| `ranking_engine.py` | 评分排序引擎（症状匹配度、药效、价格、过敏排除、年龄限制）|
| `symptom_service.py` | 症状标准化与同义词服务 |
| `history_service.py` | 筛选历史记录 |
| `config_service.py` | 筛选配置管理 |

**API 端点**：
- `POST /api/screening/symptoms/standardize` — 症状标准化
- `GET /api/screening/symptoms/synonyms` — 获取症状同义词
- `POST /api/screening/query` — 症状筛选药品
- `POST /api/screening/batch` — 批量筛选
- `GET /api/screening/config` — 获取配置
- `PUT /api/screening/config` — 更新配置
- `GET /api/screening/history` — 获取筛选历史
- `GET /api/screening/status` — 服务状态

### 5.4 组件 4：权限认证系统（auth/）

| 模块 | 功能 |
|------|------|
| `blueprint.py` | 认证 REST API（注册/登录/刷新/登出）|
| `middleware.py` | `@require_auth`、`@require_permission` 装饰器 |
| `tokens.py` | JWT 令牌生成与验证（access + refresh）|
| `schema.py` | RBAC 表结构（users, roles, permissions, role_permissions）|
| `constants.py` | 权限常量定义 |
| `audit.py` | 审计日志写入 |

**角色体系**：患者 (patient) / 医生 (doctor) / 管理员 (admin)

**API 端点**：
- `POST /api/auth/register` — 注册
- `POST /api/auth/login` — 登录（返回 access + refresh token）
- `POST /api/auth/verify` — 校验 token
- `POST /api/auth/refresh` — 刷新 token
- `POST /api/auth/logout` — 登出
- `GET /api/auth/profile` — 个人信息
- `GET /api/users` — 用户列表（管理）
- `GET /api/roles` — 角色列表
- `GET /api/permissions` — 权限列表
- `GET /api/audit/logs` — 审计日志

### 5.5 AI 医疗助手（agent/）

| 模块 | 功能 |
|------|------|
| `MedicalAgent` | Agent 主引擎，三阶段流程（表单收集 → 确认 → 药品匹配）|
| `LLMClient` | 统一 LLM 客户端，支持 OpenAI / Claude / DeepSeek |
| `MessageManager` | 对话历史管理（自动压缩与截断）|
| `SubAgents` | 症状提取（规则+LLM双模式）、表单增量采集 |
| `Tools` | query_drug / check_allergy / calc_dosage / generate_advice / submit_approval |
| `SessionManager` | 患者会话管理与 Agent 实例缓存 |

**工作流三阶段**：
1. **Phase A (basics_collection)**：采集基础信息（年龄、体重、过敏史等 Round 1 问卷）
2. **Phase B (form_collection → confirmation)**：采集症状详情（部位、性质、时长等）→ 生成总结 → 患者确认
3. **Phase C (drug_matching)**：药品查询 → 过敏检查 → 剂量计算 → 生成建议 → 提交审批

### 5.6 ROS2 集成模块（ros_integration/）

| 模块 | 功能 |
|------|------|
| `bridge.py` | 桥接适配器，保持向后兼容的 publish_task/publish_expiry_removal 接口 |
| `node_manager.py` | ROS2 节点生命周期管理 |
| `task_publisher.py` | 取药/过期清理/归队任务发布（支持 new/legacy/parallel 三种模式）|
| `state_subscriber.py` | 订阅任务状态 `/TaskState_U`、车辆状态 `/CarState_U`、药柜状态 `/CabinetState_U` |
| `state_store.py` | ROS2 状态内存缓存 |
| `message_adapter.py` | backend ↔ Unity 消息格式转换 |
| `health_monitor.py` | 健康检查与自动恢复 |
| `error_handler.py` | 错误处理与优雅降级 |

**ROS2 话题**：
- 发布：`/task_topic`（新格式）/ `/task_request`（旧格式）
- 订阅：`/TaskState_U`、`/CarState_U`、`/CabinetState_U`

### 5.7 Unity 3D 仿真（unity_simulation/）

通过 ROS-TCP-Endpoint 桥接 Unity 与 ROS2，模拟：
- AGV 小车在药房场景中的导航与取药动画
- 药柜状态展示与药品位置可视化
- 任务执行过程的可视化反馈

## 8. 配置与环境变量

关键配置项（`.env` 文件）：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `HOST` | `0.0.0.0` | 服务器绑定地址 |

| `MAX_ITERATIONS` | `15` | Agent 最大循环次数 |
| `EXPIRY_SWEEP_INTERVAL_SEC` | `3600` | 过期清扫间隔（秒）|
