# A. 组件边界与设计概述

## 一、组件定位

组件5 负责智能药品管理系统的 **Web 前端界面**，是用户与系统交互的唯一可视化入口。前端采用 **原生 HTML/CSS/JS** 技术栈（不使用 React 等框架），通过 HTTP REST API 与后端各组件通信，覆盖系统中全部四种角色（患者、医生、管理员、未登录用户）的使用场景。

```
┌──────────────────────────────────────────────────────────────┐
│                   Web 前端（组件5）                           │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────────┐     │
│  │ 登录/注册 │ │ 患者咨询 │ │ 医生审批 │ │ 管理员面板 │     │
│  │ index    │ │ patient  │ │ doctor   │ │ admin      │     │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └─────┬──────┘     │
│       │            │            │              │             │
│  ┌────┴────────────┴────────────┴──────────────┴──────┐     │
│  │              api.js — 统一 API 客户端层              │     │
│  │        JWT 令牌管理 · 错误处理 · 401 自动跳转        │     │
│  └────────────────────────┬───────────────────────────┘     │

│  └────────────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────────────┘
```

## 二、核心业务场景

### 场景1：用户登录 → 角色路由

1. 用户在 `index.html` 选择角色（患者/医生/管理员），输入用户名密码
2. 前端调用 `POST /api/auth/login`（组件4）获取 JWT Token（access + refresh）
3. Token 存入 `localStorage`，用户信息存入 `localStorage`
4. 根据用户角色自动跳转对应页面：
   - 患者 → `patient.html`（AI 医疗咨询）
   - 医生 → `doctor.html`（审批管理）
   - 管理员 → `admin.html`（仪表盘）

### 场景2：患者 AI 医疗咨询

1. 患者在 `patient.html` 与 AI 助手进行多轮对话
2. 前端调用 `POST /api/consultation`（审批/咨询 API）发送消息
3. 后端 Agent 引擎处理后返回回复 + 症状提取信息 + 药品推荐
4. 前端实时更新对话区、症状信息面板、药品推荐面板、审批状态面板
5. 患者可在"取药状态跟踪"标签页查看订单/取药任务状态
6. 患者可在"咨询与取药历史"标签页查看历史记录

### 场景3：医生审批工作流

1. 医生登录后查看待审批列表（`GET /api/approvals/pending`）
2. 查看审批详情（症状摘要、推荐药品、患者信息）
3. 执行批准（自动扣库存 + 发布 ROS2 取药任务）或拒绝（填写原因）
4. 在"审批历史"标签页查看已处理的审批记录

### 场景4：管理员药品与库存管理

1. 管理员在仪表盘查看系统状态、库存概览、预警提醒
2. 在药品管理页执行药品 CRUD、综合搜索、分类筛选
3. 批量导入/导出药品数据（JSON/CSV）
4. 库存调整、低库存/临期药品查看
5. ROS2 仿真状态实时监控

# B. 完成总结

## ✅ 完成工作概览

### 一、前端架构设计

#### 1.1 统一 API 客户端层（`js/api.js`）

所有后端 API 调用统一封装在 `ApiClient` 对象中，提供以下能力：

- **JWT 令牌自动管理**：每次请求自动携带 `Authorization: Bearer <token>` 头
- **Token 失效自动跳转**：检测 401（`AUTH_001`/`AUTH_002`）自动清除本地存储并跳转登录页
- **统一错误处理**：网络异常捕获 + 格式化错误返回
- **Query String 构建**：`_buildQuery()` 自动忽略空值参数
- **非 JSON 响应支持**：`requestRaw()` 处理 CSV 导出等特殊响应类型
- **浏览器下载触发**：`downloadDrugExport()` 支持 CSV/JSON 文件下载

封装的后端 API 端点覆盖：

| 模块 | 方法数 | 对应后端组件 |
|---|---|---|
| 认证（auth） | login / logout / refresh / profile / register | 组件4 |
| 健康检查 | health | 组件1 |
| 药品管理 | getDrugs / getDrug / createDrug / updateDrug / deleteDrug / searchDrugs / drugStats / batchImport / adjustInventory / exportDrugs / downloadDrugExport | 组件2 |
| 库存管理 | getInventory / getLowStockDrugs / getExpiringSoonDrugs | 组件2 |
| 分类管理 | getCategories / createCategory | 组件2 |
| 订单管理 | getOrders / createOrder / pickupSingle / dispense / confirmPickup | 组件2 |
| 审批管理 | createApproval / getApproval / getPendingApprovals / approveApproval / rejectApproval / completeApproval | Agent 流程 |
| AI 咨询 | sendConsultation / resetConsultation | Agent 流程 |
| 智能筛选 | screeningQuery / screeningBatch / standardizeSymptoms / getSymptomSynonyms / getScreeningConfig / updateScreeningConfig / getScreeningHistory / getScreeningStatus | 组件3 |
| ROS2 监控 | getRosStatus / getCarStates / getTaskStates / getCabinetStates / returnToQueue | ROS2 集成 |
| 用户管理 | getUsers / getUser / updateUser / getRoles / getPermissions / getUserPermissions | 组件4 |
| 审计日志 | getAuditLogs / getAuditStats | 组件4 |

#### 1.2 UI 工具函数层（`js/utils.js`）

- `formatTime()` / `timeAgo()` — 日期时间格式化与相对时间显示
- `openModal()` — 通用模态框组件
- `renderSidebar()` — 侧边栏导航动态渲染
- `pollApprovalStatus()` — 审批状态定时轮询
- `TASK_STATE_LABELS` / `TASK_STATE_COLORS` — ROS2 任务状态映射

#### 1.3 全局样式系统（`css/style.css`）

- **CSS 变量体系**：主色/成功/警告/危险/背景/文字色等全局主题变量
- **布局系统**：`.app-layout`（侧边栏 + 主内容区）、`.login-container`（登录/注册居中布局）
- **组件库**：卡片（`.card`）、表格（`.table-container`）、表单（`.form-group`/`.form-control`）、按钮（`.btn`/`.btn-primary`/`.btn-outline`）、标签（`.badge`）、警告（`.alert`）、模态框（`.modal-overlay`/`.modal-box`）、加载动画（`.spinner`）、Toast 通知（`.toast-container`）
- **聊天组件**：`.chat-container`/`.chat-messages`/`.chat-msg`/`.chat-input-area`（患者咨询页专用）
- **响应式设计**：侧边栏折叠/移动端适配

#### 1.4 通用认证与导航模式

每个需要登录的页面遵循统一的初始化模式：

```javascript
// 1. 认证守卫（自动校验 token + 角色，失败自动跳转）
const user = requireAuth('admin');  // 或 'doctor' / 'patient'

// 2. 侧边栏渲染
document.getElementById('sidebarNav').innerHTML = renderSidebar([...], currentPage);

// 3. 用户信息展示
document.getElementById('sidebarFooter').innerHTML = `头像 + 姓名 + 角色 + 退出按钮`;
document.getElementById('topUserBadge').innerHTML = `顶部用户标识`;
```

退出登录（`doLogout()`）仅清除认证信息，保留咨询历史、取药记录等本地数据。

### 二、页面功能详解

#### 2.1 登录页（`index.html`）

**功能**：
- 三角色切换标签（患者 / 医生 / 管理员），切换时自动填充对应演示账号列表
- 用户名输入框 + `<datalist>` 下拉建议（按角色显示可选账号 + 真实姓名）
- 密码输入框（默认填充 `123456` 方便演示）
- 登录按钮带 loading 防重复提交
- 登录成功后按角色自动路由跳转
- 底部演示账号提示 + 注册页链接
- 错误提示（用户名空、密码错误、网络异常等）

**对接 API**：`POST /api/auth/login`

#### 2.2 注册页（`register.html`）

**功能**：
- 用户名（必填，至少 2 字符）、邮箱（选填）、显示姓名（选填）
- 密码 + 确认密码（必填，至少 6 位，一致性校验）
- 前端表单验证 + 后端错误信息展示
- 注册成功自动跳转登录页

**对接 API**：`POST /api/auth/register`

#### 2.3 管理员仪表盘（`admin.html`）

**功能模块**：

| 模块 | 内容 |
|------|------|
| 系统状态卡片 | 后端服务状态、ROS2 仿真连接状态（车数）、数据库状态、执行中任务数 |
| 药品库存概览 | 药品种类数、总库存量、低库存预警数（<10）、已过期数、即将过期数（≤30天） |
| 预警提醒 | 过期警告（红色）、临期提醒（橙色）、低库存提醒（黄色）、正常运行（绿色） |
| 最近订单 | 最近 10 条订单（任务ID/状态/药品/数量/时间） |
| 快捷操作 | 药品管理 / 全部订单 / 刷新数据 按钮 |

**对接 API**：`GET /api/health`、`GET /api/drugs/stats`、`GET /api/orders`、`GET /api/ros/status`

**侧边栏导航**：仪表盘 → 药品管理 → 订单记录 → ROS2 监控

#### 2.4 药品管理页（`admin_drugs.html`）

前端最复杂的页面（512 行），提供完整的药品管理功能：

**工具栏**：
- 关键词搜索（名称/通用名/描述/适应症多字段模糊匹配）
- 分类下拉筛选（动态加载分类列表）
- 导出 CSV / 导出 JSON（触发浏览器下载）
- 批量导入（JSON 数组格式）
- 添加药品（打开创建表单模态框）
- 刷新按钮

**药品列表表格**：
- 列：药品ID、名称、分类、库存量、零售价、货架位置、处方药标记、创建时间、操作
- 操作按钮：查看详情、编辑、库存调整、删除（软删除）
- 分页控件（上一页/下一页 + 页码显示）

**模态框**（新增/编辑药品）：
- 基础信息：名称、通用名、分类、描述、规格、剂型、单位
- 库存与价格：数量、零售价、进货价、最低/最高库存警戒
- 位置信息：货架X、货架Y、货架ID
- 监管信息：批准文号、条形码
- 效期信息：有效期（剩余天数）
- 用药信息：用法用量、禁忌症、副作用、药物相互作用、储存条件、孕妇分级、儿童注意
- 供应信息：供应商、产地、包装规格
- 适应症管理：动态添加/删除适应症标签

**对接 API**：`GET/POST/PUT/DELETE /api/drugs`、`GET /api/drugs/search`、`POST /api/drugs/batch-import`、`GET /api/drugs/export`、`POST /api/drugs/{id}/adjust`、`GET /api/categories`、`GET /api/drugs/low-stock`、`GET /api/drugs/expiring-soon`

#### 2.5 订单管理页（`admin_orders.html`）

**功能**：
- 订单统计卡片：总数/待处理/已完成
- 订单列表表格：任务ID、状态（标签色）、药品ID、药品名称、数量、操作员、创建时间
- 刷新按钮

**对接 API**：`GET /api/orders`

#### 2.6 医生审批页（`doctor.html`）

**功能模块**：

| 标签页 | 内容 |
|------|------|
| 待审批列表 | 审批统计（总数/待审批数）、审批表格（审批ID/患者/症状/推荐药品/数量/时间/操作按钮）、查看详情模态框、批准（填写备注）按钮、拒绝（填写原因）按钮 |
| 审批历史 | 已处理的审批记录列表 |

**关键交互**：
- 批准/拒绝前弹出确认
- 操作后自动刷新列表
- 审批详情模态框展示完整症状信息、用药建议、患者信息

**对接 API**：`GET /api/approvals/pending`、`POST /api/approvals/{id}/approve`、`POST /api/approvals/{id}/reject`、`GET /api/approvals`

#### 2.7 患者咨询页（`patient.html`）

前端最复杂的页面（1,040 行），实现完整的 AI 医疗咨询体验：

**标签页结构**：

| 标签页 | 功能 |
|------|------|
| AI 医疗咨询 | 多轮对话聊天 + 右侧信息面板 |
| 取药状态跟踪 | 取药订单与任务状态实时跟踪 |
| 咨询与取药历史 | 历史咨询记录与历史取药记录 |

**AI 医疗咨询标签页**（核心功能）：

- **左侧聊天区**：
  - 对话消息列表（AI 消息 + 用户消息气泡样式区分）
  - Agent 思考步骤展示（可折叠的工具调用记录）
  - 消息输入框 + 发送按钮（支持 Enter 快捷发送）
  - 自动滚动到最新消息
  - "新咨询"按钮（重置会话）

- **右侧信息面板**：
  - **症状信息卡片**：实时展示 Agent 提取的症状/基础信息
  - **药品推荐卡片**：展示匹配的药品列表（名称/适应症/库存/价格）
  - **审批状态卡片**：审批提交后实时轮询状态（pending → approved/rejected）

**取药状态跟踪标签页**：
- 取药订单列表（任务ID/药品/数量/状态/时间）
- 任务状态实时刷新

**咨询与取药历史标签页**：
- 历史咨询记录（对话摘要/时间）
- 历史取药记录

**对接 API**：`POST /api/consultation`、`POST /api/consultation/reset`、`GET /api/approvals/{id}`、`GET /api/orders`

#### 2.8 ROS2 仿真监控页（`ros_monitor.html`）

**功能模块**：

| 模块 | 内容 |
|------|------|
| ROS2 连接状态 | 连接状态指示器（绿色/红色）、ROS2 模式标签 |
| 小车状态面板 | 3 列网格布局展示每辆小车的状态（编号/状态/位置/电量/当前任务）、货架布局可视化迷你地图 |
| 任务状态面板 | 任务列表（任务ID/类型/状态/分配小车/时间）、任务状态颜色编码 |
| 药柜状态面板 | 药柜状态列表（药柜ID/运行状态/当前操作） |
| 快捷操作 | 小车全部归队按钮 |

**特色设计**：
- ROS2 连接状态实时颜色指示（`.ros-connected` 绿色 / `.ros-disconnected` 红色）
- 小车在货架前的迷你地图可视化（有车占据的货架格高亮蓝色）
- 任务状态颜色编码：待执行(灰) → 执行中(黄) → 已完成(绿) → 失败(红)
- 每 5 秒自动轮询刷新状态

**对接 API**：`GET /api/ros/status`、`GET /api/ros/car-states`、`GET /api/ros/task-states`、`GET /api/ros/cabinet-states`、`POST /api/ros/return-to-queue`

| **组件3（筛选）** | 症状标准化、药品筛选、配置管理、历史记录 | `ApiClient.screeningQuery()` 等 9 个筛选 API 方法 |
| **组件1（基础）** | 统一响应格式 `{success, data, pagination, error}` | 前端 `ApiClient.request()` 统一解析两种错误格式（嵌套 `error` 和扁平 `error_code`） |
| **ROS2 集成** | 状态查询、小车/任务/药柜状态 | `ApiClient.getRosStatus()` 等 ROS2 状态 API |
| **Agent 引擎** | `POST /api/consultation` AI 对话 | `ApiClient.sendConsultation()` |

### 四、前端对两种错误格式的兼容处理

根据组件1 的接口文档，后端存在两种错误响应格式：
- 业务 API（药品等）：`{ "success": false, "error": { "code": "...", "message": "..." } }`（嵌套格式）
- 鉴权 API（组件4）：`{ "success": false, "error_code": "AUTH_001", "message": "..." }`（扁平格式）

前端 `ApiClient.request()` 方法通过检测 `data.error_code` 字段实现统一兼容：
- 鉴权失败（401，`AUTH_001`/`AUTH_002`）→ 清除本地存储并跳转登录页
- 权限不足（403）→ 仅返回错误信息，不跳转
- 其他错误 → 统一通过 `data.error?.message` 或 `data.message` 提取错误信息

### 五、前端特色设计

#### 5.1 渐进增强的用户体验

- **Loading 状态**：所有 API 调用期间显示 spinner 动画，避免空白等待
- **空状态提示**：无数据时显示友好的空状态图标 + 说明文字
- **Toast 通知**：操作结果（成功/失败）以 Toast 形式在右下角弹出，3 秒自动消失
- **按钮防重复**：登录/提交按钮在请求期间 disabled + 文字变为"处理中..."
- **侧边栏响应式**：小屏幕下侧边栏可折叠（`.menu-toggle` 按钮）

#### 5.2 本地数据保留策略

`doLogout()` 退出时只清除认证相关数据（`auth_token`、`refresh_token`、`currentUser`），**保留**咨询历史、取药记录等本地非敏感数据。患者重新登录后可继续查看之前的记录。

#### 5.3 演示友好设计

- 登录页默认密码 `123456`
- 按角色提供用户下拉建议列表（含真实姓名）
- 底部直接展示演示账号信息
- 注册页与登录页之间便捷跳转

#### 5.4 实时状态轮询

- ROS2 监控页每 5 秒自动刷新小车/任务/药柜状态
- 患者审批状态支持轮询（`pollApprovalStatus()` 工具函数）
- 仪表盘数据支持手动刷新按钮
